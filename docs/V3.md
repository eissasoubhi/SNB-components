# SNB-components v3

SNB-components v3 is a deliberately small shared core for the Summernote Bricks ecosystem. V3 is the maintained product line and lives directly at the repository root.

## Scope

The package contains only primitives that are useful across more than one brick:

- semantic/versioned brick metadata helpers;
- DOM lookup and parsing helpers;
- narrow Summernote context integration helpers;
- history-safe DOM mutation helpers.

It is **not** a UI framework and does not own brick-specific dialogs, rendering, validation, source loading or lifecycle.

## Runtime contract

- native DOM;
- no React/Vue runtime;
- no direct Bootstrap dependency;
- no jQuery or Summernote runtime dependency bundled into the package;
- consumers pass the Summernote context only where an operation needs it.

Because the core does not import jQuery or Summernote at runtime, the v3 candidate intentionally has no host peer dependencies. Concrete plugins such as Heading and Gallery declare their own jQuery/Summernote peer ranges.

## Distribution

The root package stages the v3 release candidate as `3.0.0-rc.0` with:

- ESM runtime: `dist/index.js`;
- UMD/CommonJS-compatible browser runtime: `dist/index.umd.cjs`;
- ESM TypeScript declarations: `dist/types/index.d.ts`;
- CommonJS TypeScript declarations: `dist/types/index.d.cts`;
- conditional package `exports` that pair ESM/NodeNext consumers with `.d.ts` and CommonJS/Node16 consumers with `.d.cts`;
- only distribution files and public documentation included in the npm package.

The permanent package gate creates the exact npm tarball, installs it in a clean consumer, verifies matching ESM/CommonJS/browser runtime exports, and compiles consumers through both TypeScript NodeNext/ESM and Node16/CommonJS package resolution. The Node 22/24 workflow also requires reproducible tarball bytes and verifies archived artifact digests after the GitHub Actions upload/download round trip.

The former maintained parallel `package.v3.json` / `v3-tooling` layout has been removed from the product line. Repository history remains preserved, but new v3 changes target the root package and committed root lockfile.

## Release boundary

SNB-components remains independent from the coordinated Bricks/Heading/Gallery publication train. Its release-readiness workflow verifies package/lock identity, the full package gate, exact `npm pack`, SHA-256/size evidence and artifact archival. That evidence records `publishAuthorized: false` and does not itself authorize npm or GitHub publication.

A future SNB-components release requires its own explicit publication workflow and proof based on its own public-head/reproducibility gates.

## Compatibility policy

The shared core itself is browser-library code and does not claim Summernote interface compatibility independently. Summernote compatibility is proven by the concrete Heading/Gallery and Bricks composition Playwright matrices.

Breaking changes to exported metadata schemas or helpers require a major version after v3 becomes stable.
